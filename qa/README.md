# QA: сценарии «как у реальных людей»

Обычные тесты гоняются на быстрой машине рядом с сервером — именно поэтому они не ловят то, на чём
реально ломаются зрители. Здесь сценарии с плохой сетью, потерями, обрывами и разными браузерами.

```bash
cd qa && npm i            # playwright-core; браузеры берутся из установленных playwright
QA_BASE=https://watch.kerry.zone QA_VIDEO="https://vkvideo.ru/video-195334327_456241064" node run.mjs
node run.mjs --only slow-viewer,flaky-segments
```

Переменные: `QA_BASE` (сайт), `QA_VIDEO` (ссылка на видео), `QA_CHROME` (путь к chrome, по умолчанию
из `%LOCALAPPDATA%/ms-playwright`), `QA_WEBKIT` (путь к webkit для iPhone-сценария).

Каждый сценарий печатает `PASS`/`FAIL` с причиной и числами; код выхода ≠ 0, если что-то упало.

| Сценарий | Что имитирует | Что считается успехом |
|---|---|---|
| `baseline` | хороший интернет, двое | оба играют, расхождение < 1 с |
| `slow-viewer` | у друга ~600 кбит/с и RTT 400 мс | комната встаёт на паузу с баннером, не рассинхронизируется, после улучшения сети едет дальше |
| `flaky-segments` | 8 % запросов сегментов падают, 10 % задерживаются на 3 с | воспроизведение не умирает, расхождение < 2 с |
| `socket-drop` | обрыв WebSocket на 8 с (метро, лифт) | после возврата состояние комнаты восстановилось |
| `reload-mid-play` | F5 во время просмотра | вернулся на ту же секунду ±2 с |
| `clock-skew` | часы клиентов уехали на минуты | все на одной секунде |
| `late-join` | зашёл через 5 минут | догнал комнату ±1.5 с |
| `iphone-webkit` | Safari на iPhone (нативный HLS) | видео стартует, есть звук/кадр |
| `crowd` | 8 зрителей разом | все в комнате, нет ошибок |
| `mobile-layout` | экран 390×844 | нет горизонтальной прокрутки, видео сверху, чат и поле ввода видны |
